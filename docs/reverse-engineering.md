# NOVA98 协议逆向笔记

## 实验 2：断电重读诊断（2026-08-25）

拔插 USB 后直接 GET_REPORT（零写入）：

```text
00 00 00 00 ... 全零
```

结论：
- 上一次读到的 `04 18` 是设备真实寄存器状态（非 macOS 缓存假象）；
- 设备「存储最后一条命令并回显」机制成立；
- **写入通道确认可用，BEGIN 命令被设备接受。**

风险仍存：图像头（`04 72 ...`）的字段布局是否与 F108 Pro 一致未验证。
缓解措施：单帧、纯黑、目标槽位选用户自定义图片槽（可用官方 App 恢复），
不上传多帧、不碰 GIF 区。

## 实验 1：BEGIN 探测（2026-08-25）

- 发送：`SET_FEATURE(report 0x00)` payload `04 18`（F108 Pro 的 BEGIN 命令）到
  Interface 3 / Usage Page `FF67`。
- 读回（GET_REPORT, 64 字节）：

```text
00 04 18 00 00 00 00 ... 00
```

## 观察

1. 设备**原样回显**了收到的命令（`04 18`），说明：
   - 写入通道和 Feature Report 机制工作正常；
   - 设备将最后一条命令保存在寄存器中，与 F108 Pro「SET 后必须 GET」的行为类似。
2. 与 F108 Pro 不同：F108 Pro 的响应是 `byte[3] = 0x01` 的 ACK 签名；
   NOVA98 返回的是命令回显，`byte[3] = 0x00`。
   - 可能含义 A：该固件用「回显」表示接受（不同主控的方言）。
   - 可能含义 B：byte[3] 是状态位，0x00 = 失败/未完成。
   - 无法区分，不能靠猜继续发图像头（会触发 Flash 写入路径）。

## 结论

控制命令集**未确认兼容** F108 Pro。按执行计划停止条件 3，
停止一切后续写入，转入抓包/对照分析。

## 下一步候选（按优先级）

1. **断电重读（只读）**：拔插键盘后直接 GET_REPORT，确认空闲态是否为全零。
   - 若全零 → 回显确实是「收到命令后的状态」，写入通道确认可用。
   - 若仍显示 `04 18` → 可能是 macOS hidapi 缓存假象。
2. **官方软件抓包**：在 Windows 上用 USBPcap/Wireshark 抓 A HUB 上传单张图片，
   记录完整命令序列；或在 macOS 用 Wireshark XHCIDAR 等。
3. **WebHID Hook**：若官方有网页配置器，用 Chrome WebHID log 观察报告字节。
4. 对照同厂商（AULA 非SONiX 主控）其他型号的开源项目。
